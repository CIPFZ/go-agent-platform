# 实施路线图

当前仓库已实现 P1-P6 的可运行最小闭环：Gateway/Agent/任务/执行器/策略/审计/指标/CMS HTTP 边界和部署指导均已提供。持久化数据库、证书签发和具体 CMS 页面仍通过接口接入，不在此仓库内复制实现。

路线按“先把状态和边界做对，再逐步增加动作能力”的顺序推进。

## P0：项目骨架（已完成）

- 建立独立 GitHub 仓库和 Ubuntu 工作目录。
- 拆分 `gateway` 与 `guest-agent` 入口。
- 固定 CMS、Gateway、Agent 的职责边界。
- 添加基础文档、Go module 和可运行入口。

验收：本地和 Ubuntu 均可执行 `go test ./...`，工作副本跟踪 GitHub `main`。

## P1：注册、心跳和协议骨架

- 定义版本化请求/响应 envelope、错误分类和时间字段。
- 实现 Agent 注册、心跳、能力摘要和撤销。
- 实现 Gateway 的在线状态和最后心跳时间。
- 为 HTTP 客户端设置 TLS、连接超时、重试和退避基础配置。

验收：启动一个 Gateway 和一个 Agent，可以看到注册、心跳和离线状态；重启 Agent 不会创建重复身份。

## P2：任务队列和生命周期

- 实现任务创建、按 Agent 拉取、租约、确认和结果回传。
- 加入任务 ID、幂等键、超时、取消和有限重试。
- 添加全局、调用方和 Agent 级并发/队列限制。
- 先存储结构化任务和结果，再接入持久化数据库。

验收：断开网络、重复提交和 Agent 重启场景下，任务状态不会无故丢失或重复执行。

## P3：命令执行

- 以 argv 数组实现 `command.exec`。
- 支持工作目录、受限环境变量、stdout/stderr 上限和退出信息。
- 加入进程树清理、取消宽限期和超时处理。
- 增加第一版命令策略与审计事件。

验收：安全测试命令可以完成；超时、取消、超大输出和非零退出码都有明确结果。

## P4：截图、文件和桌面能力

- Agent 启动时探测截图工具、显示会话和桌面能力。
- 实现截图制品上传、尺寸/格式/哈希和过期策略。
- 实现受限目录的文件读写和大小限制。
- 再评估浏览器、鼠标键盘等需要图形会话的动作。

验收：有桌面环境的 VM 可以返回可验证截图；无桌面环境会返回能力不足，而不是卡住任务。

## P5：CMS 对接

- CMS 保存 VM 与 Agent 的绑定关系和能力摘要。
- 在虚拟机详情页展示 Agent 在线状态、最近心跳和任务摘要。
- 为 CMS 提供创建任务、查看结果和取消任务的后端封装。
- 保持 CMS 的 VM 生命周期接口与 Agent 任务接口分离。

验收：从 CMS 选择一台 VM 可以提交一个受限测试任务，并在页面看到完整状态链路。

## P6：部署、观测和发布

- 提供 Gateway systemd/容器部署和 Agent 镜像安装方案。
- 添加结构化日志、指标、健康检查和版本兼容检查。
- 建立 CI 的格式化、测试、静态检查和构建产物。
- 制定 Agent 升级、回滚、凭据轮换和制品清理流程。

验收：新 VM 镜像可自动安装 Agent；Gateway 和 Agent 升级失败时可以回滚到上一版本。

## 下一 session 建议任务

下一 session 直接从 P1 开始，建议拆成三个连续小步骤：

1. 先写 `internal/protocol` 的类型和错误模型，不接数据库。
2. 再实现 Gateway 的注册/心跳内存存储和健康接口。
3. 最后让 guest-agent 完成注册、定时心跳和优雅退出。

这样下一步开发有清晰的可运行闭环，后续队列和动作处理器可以在稳定的身份模型上扩展。
