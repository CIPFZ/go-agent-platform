# 安全与运行边界

这个服务可以在虚拟机中执行命令和访问桌面，因此安全边界必须和功能一起设计，而不是上线后再补。

## 身份与连接

- 每台 Agent 有稳定的实例 ID，注册凭据不能写入普通日志。
- Gateway 只接受已注册 Agent 的心跳和任务结果，注册、轮换和撤销都要有审计事件。
- 生产环境使用 HTTPS；证书校验不能为了调试而全局关闭。
- Agent 只主动访问配置的 Gateway 地址，不提供不必要的入站监听端口。

## 命令安全

- 默认采用 argv 数组，避免把用户输入拼接成 shell 命令。
- 允许列表、拒绝列表和风险等级由策略层判断；策略命中后返回阻断原因或“需要确认”，不静默执行。
- `sudo`、关机、删除、改网络、改用户、挂载、写入宿主机共享目录等动作默认属于高风险。
- 命令必须有工作目录、环境变量范围、最大运行时间、最大输出和最大进程数限制。
- 任务取消需要发送停止信号并在宽限期后强制结束，不能只把数据库状态改成 cancelled。

## 文件和制品

- 文件读写限制在明确的工作区或动作允许的目录。
- 上传和下载限制大小、类型和总并发，并在结果中记录哈希。
- 临时制品设置过期时间，避免截图和日志无限积累。
- 日志和结果默认脱敏，不能输出令牌、密码、私钥或完整环境变量。

## 资源保护

- Gateway 设置全局、调用方和 Agent 三级队列/并发上限。
- Agent 设置本机 Worker 上限、单任务资源预算和输出缓冲上限。
- 长轮询、上传、日志流和截图请求都必须有超时和取消路径。
- 服务应暴露队列长度、运行任务数、失败数、超时数和 Agent 在线数，便于发现资源耗尽。

## 审计

每个任务至少记录调用方、Agent、动作类型、参数摘要、策略结论、时间线、结果摘要和制品哈希。危险操作还需要记录确认人或确认来源。审计记录与任务结果分离保存，不能因为清理临时日志而丢失。
